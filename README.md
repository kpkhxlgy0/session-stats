# Session Stats

Codex++ tweak，在当前会话输入框底部显示：

```text
2 turns · 33 steps · 209 tok/s     11.7M tok · Cache hit 96%
```

不显示上下文占用。统计行居中放在输入框下方已有的留白内，不占布局高度、不把输入框往上顶。
适配浅色、深色主题，窄窗口可横向滚动；鼠标停在指标上可查看口径。

支持本地及 Codex 已连接的远程主机会话，包括 Remote Control 主机。运行端读取自己的会话日志，
生成小型统计快照，本地与远程显示同一版本的结果。共享统计需要两端都更新并启用 Session Stats。
接收端只读取统计快照，不扫描远程历史目录，也不会回退下载原始会话日志。

## 指标口径

| 指标 | 计算方式 |
| --- | --- |
| turns | 当前有效日志历史中不同 `turn_id` 的数量 |
| steps | 不同 `response_id` 的模型响应数量，不是工具调用次数 |
| tok/s | 包括 fork 继承历史在内的有效轮次官方 `usage.output_tokens`（包含推理）总和 ÷ 对应模型活跃秒数总和 |
| tok | 普通会话使用官方累计 Token；本地分叉会话仅累计分叉后每次响应的用量。输入 + 输出，缓存输入不重复相加 |
| Cache hit | 累计缓存输入 Token ÷ 累计输入 Token |

模型活跃时间取 `item_completed` 中 `Reasoning` 和 `AgentMessage` 的
`started_at_ms` / `completed_at_ms` 区间并集，重叠时间只算一次，排除工具执行、I/O 和用户等待。
TPS 跨用户轮次累计，在响应完成后更新。进入新轮会保留已有会话平均值，
`~` 表示正在等待新样本：新轮尚未形成有效样本，或新的模型/工具活动对应的用量尚未到达。
仅汇总用量与计时已匹配的样本，不把待匹配的新区间提前计入分母。
缺少完整用量、模型计时、轮次起点或有效时长的轮次不进入分子和分母；完全没有有效样本时显示 `—`，
不会通过字符数估算 Token。有效的零输出轮次仍计入耗时。
开始与结束时间相同的记录贡献 0 毫秒，不会让同轮其他有效计时失效；全轮不足 100 毫秒不作为有效样本。

这是依据客户端日志计算的会话平均模型速度，包含模型处理阶段的开销，不是服务端测得的纯解码速度。
先汇总输出与耗时再相除，不直接平均各轮 TPS；例如两轮各输出 1000 tokens、活跃时间分别为 5 秒与 20 秒，
会话平均为 `2000 / 25 = 80 tok/s`。不同轮次分别计算区间并集，跨轮只汇总有效样本，不计用户等待。
旧日志可能只有累计 Token，而没有 steps 或 TPS 所需字段；截断或压缩的历史也以可读日志为准。
分页分叉会话的 TPS 包含分叉点之前继承的有效历史，再与当前分支的新样本一起累计；
父会话在分叉之后新增的内容不参与。多层 fork 和续接仍按各自的历史边界截断，重放响应只算一次。
轮次、steps、Token 和缓存命中率继续只统计当前分支；TPS 的用量与耗时单独汇总。
继承历史缺失、损坏或无法唯一确认时，TPS 显示 `—`，不会退回仅当前分支的部分平均值；
能够独立确定的当前分支计数仍然显示。缺少单次响应用量时，相应累计指标显示 `—`，不回退到包含父历史的累计值。

TPS 思路参考 [dongyue-19/codex-statusbar](https://github.com/dongyue-19/codex-statusbar)
的 `TpsTracker.cs`，本项目独立实现。

## 安装

在 Codex++ Settings → Tweak Store 中搜索 **Session Stats** 并安装，最低运行时版本为 `1.0.6`。
Store 固定到审核过的完整提交 SHA；安装后无需运行 `npm install` 或构建。

源码：[kpkhxlgy0/session-stats](https://github.com/kpkhxlgy0/session-stats)。
版本：[v0.4.1](https://github.com/kpkhxlgy0/session-stats/releases/tag/v0.4.1)。

## 本地 Inject / Uninject

已安装 Codex++ 时，可在源码目录用 PowerShell 7 执行：

```powershell
pwsh -File .\Inject-CodexPlusPlus.ps1
pwsh -File .\Uninject-CodexPlusPlus.ps1
```

两者都支持 `-CheckOnly`，只查看将执行的操作。脚本使用 `CODEX_PLUSPLUS_HOME`，
未设置时使用 `%APPDATA%\codex-plusplus`。

Inject 创建指向本目录的开发链接并启用 Session Stats，重复执行安全。
Uninject 禁用此 tweak，并移除指向本目录的开发链接，保留源码。
如果已从 Store 安装，脚本仅启用或禁用该副本，不替换或删除它。
脚本不会安装、升级或卸载 Codex++，也不影响其他 tweak。

## 开发与验证

需要同级目录中的规范 Codex++ checkout `../codex-plusplus`，已构建且版本不低于 `1.0.6`。

```powershell
git clone https://github.com/kpkhxlgy0/session-stats.git
cd session-stats
npm ci
npm test
npm run validate
npm run install:local
```

安装通过规范仓库提供的开发链接命令，将 `%APPDATA%\codex-plusplus\tweaks\com.kpk.session-stats`
链接到当前源码目录；运行时自动热重载。没有后台安装脚本、常驻开发进程或运行时 npm 依赖。
可在 Codex++ Tweaks 管理界面禁用 Session Stats。禁用会移除统计条、监听器、定时器及本 tweak 的 IPC。

测试也可独立运行，只需 Node.js 20 或更高版本；原生 Zstd 压缩历史相关验证需要 Node.js 22.15 或更高的受支持版本。
`validate` 和 `install:local` 才需要同级 Codex++ checkout。
已在 Windows 的 Codex 桌面端验证实际加载；其他平台的原生界面尚未实测。

## 数据与兼容性

- 运行端通过现有本地解析器读取 `$CODEX_HOME/sessions` 和 `archived_sessions`；未设置时使用 `~/.codex`。
  支持续接日志、归档和分叉，按 `history_base` 的字节/记录数边界还原有效历史，排除废弃尾部。
  fork 的 TPS 会追溯声明的父会话前缀，父历史不会混入当前分支的其他计数。计时与用量匹配、响应去重和跨轮累计平均公式保持一致。
- 运行端也可读取 `.jsonl.zst` 压缩历史，只解码所需前缀，不把解压后的聊天内容写入磁盘。
  压缩历史按最多 64 KiB 的输入/输出块流式解压，消费完成后才继续读取；每个统计器串行解压，
  原生 Zstd 窗口上限为 128 MiB。不缓存解压日志，不再因文件超过 64 MiB 或解压前缀超过 256 MiB 而拒绝读取。
  只保留统计累加器及最多 1024 项元数据、1024 项边界校验结果；单条日志仍限制为 8 MiB。
  文件版本未变化时复用已有统计，重复刷新不会重新解压父历史；文件变化后重新校验并重建，避免混用或重复计算。
  原生 Zstd 不可用、窗口超限、必要历史损坏或无法确认边界时，相关 TPS 保持未知。
  同一日志同时存在普通和压缩副本时优先读取普通副本；远程接收端仍然只读取统计快照。
- 快照位于 `$CODEX_HOME/.session-stats/<会话 UUID>.json`，只包含统计值、会话/发布者标识、递增版本及更新时间，
  不包含聊天正文、原始日志路径或认证信息；每份最多 16 KiB。本地底栏返回同一次成功发布的样本。
- 运行端约每 2 秒检查已关注会话；数值变化立即原子替换快照，未变化时每 10 秒更新心跳。
  后台每 15 秒发现最近 8 个会话，最多跟踪 32 个会话；不要求会话一直处于前台。
- 较旧、尚未生成快照的远程会话通过轻量刷新请求触发运行端计算。
  接收端最多每 10 秒更新一次 `.session-stats/requests/<会话 UUID>.<请求 UUID>.json`；
  每次请求使用新的文件名，避免过期清理误删新请求。请求最多 1 KiB，只含固定协议标识、会话 ID 和时间，由运行端约每 2 秒检查。
  普通任意文件写入不对接收器开放；请求位置、目录类型和已有文件归属必须通过校验。
- 接收端通过现有 RC 连接定位当前会话，只读取固定快照路径。
  每次读取有独立的大小和超时限制；界面每次等待最多 750 毫秒后返回已确认状态，后台继续读取。
  缺失、断线或过期时提示并重试，不启动原始日志下载。
- 校验会话、固定来源、数值、快照版本及发布时间；超过 30 秒未更新或来自未来超过 5 秒的数据不可用。
  旧发布者或倒退版本不能覆盖已确认的新样本；原子替换快照时不会误把正常文件替换当成身份失败。
- 原始会话日志保持只读。组件只生成自己的统计快照、刷新请求和短暂的原子写入文件，保留无关文件；
  停用会停止后台发布和读取，并清理自己持有的临时文件。最终快照可能保留，过期后不会作为当前数据使用。
  生成目录若位于本 tweak 的热加载目录内，会停止发布以避免循环重载。
- 普通更新只传很小的快照。首次按需生成仍取决于运行端读取本机历史所需时间；
  网络延迟可能使两端暂时看到不同版本，同一快照版本的全部统计值完全一致。
- 请求和缓存按主机与会话隔离。分块响应按传输 ID 隔离并限制总内存，多个 RPC 的数据不会互相覆盖。
  切换、停用及过期操作不能把旧结果写入新会话的底栏。
- 根据当前输入框的主机 ID 和会话 ID 绑定，跳过首页、云端任务和无法唯一识别的输入框。
  Electron 隔离环境下，只通过已有主页面桥接读取最小身份，不传递 React 对象或聊天内容。
- 远程桥接及输入框绑定依赖 Codex 内部协议，已按 Windows 安装包 `26.1021.3705.0` 核对。
  其他平台的原生界面尚未实测；后台文件与协议逻辑有自动化回归覆盖。

## 文件

- `index.js`：主进程和渲染进程生命周期、IPC。
- `src/metrics.cjs`：用量去重、缓存命中率、模型时间并集和 TPS。
- `src/session-store.cjs`：会话文件发现、增量只读读取和缓存。
- `src/snapshot.cjs`：统计快照及按需刷新请求协议。
- `src/snapshot-publisher.cjs`、`src/snapshot-discovery.cjs`：运行端后台发现、计算和原子发布。
- `src/snapshot-remote-store.cjs`：远程快照读取、时效与版本校验。
- `src/remote-transport.cjs`：现有主机连接的快照读取、受限刷新请求、分块隔离和取消清理。
- `src/binding.cjs`：当前输入框会话绑定。
- `src/renderer.cjs`：统计条、会话切换和清理。
- `test/`：指标、文件轮换、隔离环境、切换会话和热重载回归测试。
